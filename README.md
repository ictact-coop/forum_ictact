# 오늘의 디지털 수다 💬

IT와 공익활동에 대한 온라인 공론장 — 첨부된 기획안·시안을 바탕으로 만든
"경험을 붙이고 서로 공감하는 디지털 벽" 웹앱입니다.

부스 방문객이 QR코드/스마트폰 또는 현장 태블릿으로 30초~1분 안에 짧은 경험을
남기고, 다른 사람의 이야기에는 글 없이 반응만으로도 참여할 수 있습니다. 대형
화면에는 실시간(준실시간) 게시판을 띄워 참여를 유도합니다.

## 화면 구성

| 경로 | 용도 |
| --- | --- |
| `/` | 참여 플로우 — 소개 → 질문(보드) 선택 → 감정 선택 → 한마디 작성 |
| `/board` | 실시간 게시판 — 방문객이 다른 사람 글을 구경하고 공감 반응을 남기는 화면(태블릿/스마트폰) |
| `/display` | 대형 화면·키오스크용 게시판 — QR코드와 통계, 게시글이 크게 보이는 읽기 전용 화면 |
| `/admin` | 운영자 페이지 — 승인 대기 글 검수, 숨김/삭제, 보드별 승인 방식 설정, 운영자 계정 관리, CSV 내보내기 |
| `/manage` | 사용자 관리 페이지 — 회원가입/로그인 후, 임원이 사용자 등급(임원/조합원/일반인)을 관리 |

## 기획안 반영 내용

- **질문(보드) 설계**: 메인 질문 3개(😵 좀 힘들었어요 / ✨ 이건 좋았어요 / 💭 이랬으면
  좋겠어요) + 추가 질문 3개를 "3개 먼저 보여주고 더보기로 확장"하는 구조로 구현.
- **쓰기 부담 최소화**: 질문 선택 → 감정 선택(건너뛰기 가능) → 한마디 작성(300자)
  순서의 4단계 플로우.
- **안전한 익명성**: 닉네임은 선택 입력이며, 입력창 하단에 개인·단체를 특정하지
  않아도 된다는 안내 문구를 노출.
- **반응도 참여로 인정**: 댓글 없이 ❤️ 공감해요 / 💡 나도 이런 생각 / 😮 처음
  생각해봤어요 세 가지 가벼운 반응만 제공.
- **운영자 승인(준실시간) 게시**: 보드별로 "운영자 승인 후 게시" 여부를 관리자
  페이지에서 언제든 켜고 끌 수 있습니다. **기본값은 모든 보드가 실시간 공개**이며,
  어떤 보드를 승인제로 할지는 아직 정해지지 않았으므로 행사 전 운영진 협의 후
  관리자 페이지에서 설정하면 됩니다.
- **여러 운영자가 함께 관리**: 운영자 계정을 여러 개 만들어 각자 로그인할 수
  있고, 어떤 글을 누가 승인/숨김 처리했는지 목록에 "처리: 아이디"로 표시되어
  중복 작업 없이 분담할 수 있습니다.
- **운영/안전**: 관리자 페이지에서 글 숨김·삭제, 행사 종료 후 CSV(텍스트+반응 수)
  내보내기 지원.
- **현장 운영**: `/display`는 QR코드와 실시간 게시판을 함께 보여주는 대형 화면용,
  `/board`는 개인 스마트폰·키오스크 태블릿에서 구경 + 반응까지 가능한 화면.

## 실행 방법

```bash
npm install
cp .env.example .env.local   # ADMIN_USERNAME / ADMIN_PASSWORD를 실제 값으로 변경하세요
npm run dev                  # 개발 서버, http://localhost:3000
```

운영(행사 당일) 배포:

```bash
npm run build
ADMIN_USERNAME=아이디 ADMIN_PASSWORD=비밀번호 npm run start
```

`ADMIN_USERNAME`/`ADMIN_PASSWORD`는 **서버를 처음 띄울 때 딱 한 번, 최초
운영자 계정을 만드는 용도**입니다. 이후에는 그 계정으로 `/admin`에 로그인해서
다른 운영자 계정을 자유롭게 추가/삭제할 수 있습니다(아래 "운영자 페이지
사용법" 참고). 계정 정보는 데이터베이스에 저장되므로, 두 번째 실행부터는
이 환경변수를 지정해도 무시됩니다.

## 사용자 관리 페이지(`/manage`) 사용법

방문객이 글을 쓰는 것과는 별개로, "사용자" 계정을 만들어 **임원 / 조합원 / 일반인** 세 등급으로
구분해 관리할 수 있는 화면입니다. `/admin`의 운영자 계정과는 완전히 별개의 로그인 체계입니다.

1. `/manage`에 처음 접속하면 로그인/회원가입 화면이 뜹니다. 계정이 없으면 "회원가입" 탭에서
   아이디·비밀번호(6자 이상)·이름(선택)을 입력해 가입합니다.
2. **가장 처음 가입하는 사람은 자동으로 '임원' 등급이 됩니다.** 이후 가입자는 모두 '일반인'으로
   시작하며, 등급은 임원만 올리거나 내릴 수 있습니다.
3. 임원으로 로그인하면 전체 사용자 목록이 보이고, 각 사용자 옆의 등급 선택창에서 임원/조합원/
   일반인 중 하나로 바로 바꿀 수 있습니다. 필요 없는 계정은 "삭제"로 없앨 수 있습니다.
4. 조합원·일반인 등급으로 로그인하면 본인 등급만 확인할 수 있고, 사용자 목록·등급 변경 기능은
   보이지 않습니다.
5. 마지막 남은 임원 계정은 등급 강등이나 삭제가 되지 않아, 관리 권한이 있는 계정이 하나도
   없어지는 상황을 막아줍니다.

## 운영자 페이지 사용법

1. `/admin` 접속 후 최초 운영자 계정(`ADMIN_USERNAME`/`ADMIN_PASSWORD`)으로 로그인합니다.
2. "운영자 계정 관리"에서 함께 운영할 사람 수만큼 계정을 추가합니다. 이후 각자
   자기 계정으로 로그인해서 동시에 관리할 수 있습니다.
3. "보드별 게시 방식"에서 승인이 필요한 보드를 협의해 토글합니다(기본은 전부
   실시간 공개).
4. 승인 대기 글은 목록에서 "승인" 또는 "삭제"를 선택합니다.
5. 부적절한 게시글은 언제든 "숨기기"로 게시판에서 즉시 내릴 수 있습니다. 처리한
   운영자 아이디가 글에 표시되어 누가 뭘 처리했는지 알 수 있습니다.
6. 행사 종료 후 "CSV 내보내기"로 전체 글과 공감 수를 내려받습니다.

계정을 잘못 추가했거나 행사 후 정리할 때는 같은 화면에서 삭제할 수 있습니다.
단, 본인 계정과 마지막 남은 운영자 계정은 실수로 잠기지 않도록 삭제할 수
없습니다.

## 운영 환경 추천 (유지비 절감)

이 앱은 데이터를 **libSQL(=SQLite 호환)** 에 저장하는데, 로컬 파일과 서버리스
호스팅형 DB를 `DATABASE_URL` 환경변수 하나로 전환할 수 있게 만들어져 있습니다.
행사가 짧게(2일) 운영된다는 점을 고려하면 아래 순서로 검토하는 것을 권장합니다.

### 1순위 — 완전 무료: Vercel(Hobby) + Turso

별도 서버 관리 없이, 평소 트래픽이 크지 않은 부스 행사에 가장 적합합니다.

1. [Turso](https://turso.tech)에서 무료 계정으로 데이터베이스를 하나 만듭니다.
   ```bash
   turso db create digital-chat
   turso db show digital-chat --url        # DATABASE_URL 값
   turso db tokens create digital-chat      # DATABASE_AUTH_TOKEN 값
   ```
2. 이 저장소를 [Vercel](https://vercel.com)에 연결해 Hobby(무료) 플랜으로
   배포합니다.
3. Vercel 프로젝트 환경변수에 `DATABASE_URL`, `DATABASE_AUTH_TOKEN`,
   `ADMIN_USERNAME`, `ADMIN_PASSWORD`를 등록합니다.
4. 배포된 주소가 곧 QR코드로 안내할 참여 주소이자 `/display`, `/admin` 주소가
   됩니다.

Turso 무료 티어와 Vercel Hobby 플랜 모두 이 정도 규모(2일, 방문객 단위 트래픽)
행사에는 넉넉하며, 행사 후 사용하지 않으면 비용이 들지 않습니다.

#### Vercel 배포 시 자주 겪는 문제

- **"포스트잇 붙이기"를 누르면 네트워크 에러가 나고, Vercel 로그에
  `ENOENT: no such file or directory, mkdir '/var/task/data'`가 찍힘**
  → `DATABASE_URL`이 실제로는 비어 있다는 뜻입니다. Vercel은 파일시스템이
  읽기 전용이라 로컬 SQLite 파일을 만들 수 없는데, `DATABASE_URL`이
  안 읽히면 로컬 파일 방식으로 되돌아가려다 이 오류가 납니다. 아래를 확인하세요.
  1. Vercel 프로젝트 → Settings → Environment Variables에서 `DATABASE_URL`,
     `DATABASE_AUTH_TOKEN` 이름이 정확한지(오타·공백 없는지) 확인합니다.
  2. 변수를 적용할 **Environment**(Production/Preview/Development) 체크박스가
     실제로 접속 중인 배포 환경과 맞는지 확인합니다.
  3. **환경변수는 저장만 해서는 기존 배포에 적용되지 않습니다.** Deployments
     탭에서 최신 배포를 다시 "Redeploy" 하거나, 새 커밋을 푸시해 다시
     배포해야 합니다.
  4. 배포 후 `https://<내-주소>/api/health`에 접속해 `"database": "remote(DATABASE_URL)"`
     로 나오는지 확인합니다. `"local(file)"`로 나오면 여전히 환경변수가
     적용되지 않은 것입니다.

### 2순위 — 직접 관리형 서버가 필요할 때

Vercel/서버리스 대신 하나의 URL로 계속 띄워두는 서버를 원한다면, 영구 디스크를
제공하는 소규모 인스턴스에 `DATABASE_URL`을 지정하지 않고(로컬 파일 저장)
`npm run build && npm run start`로 그대로 실행하면 됩니다. Fly.io의 최소
사양 머신(볼륨 포함)이나 월 4~6천원대의 소형 VPS 정도면 충분하고, 행사 종료
후 인스턴스를 내리면 유지비가 발생하지 않습니다.

로컬 파일로 운영할 경우, 기획안 8장의 "1일차 종료 시 데이터 백업" 체크리스트에
따라 행사 중간에 `data/forum.db` 파일을 주기적으로 복사해두는 것을 권장합니다
(Turso를 쓰면 이 백업 작업이 필요 없습니다).
